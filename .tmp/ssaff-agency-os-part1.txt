SSAFF

Architecture  ·  Hierarchy  ·  Agent Roles  ·  Naming  ·  Roadmap  ·  CoS

You make all final decisions. No agent spends money, pauses campaigns, or changes strategy without your approval. Every agent surfaces information, makes recommendations, and executes only pre-approved actions.

2. SYSTEM MAP
Five layers. Each layer has one job and communicates only up or down — never sideways.

Layer
Role
LAYER 0 — You
All final decisions. Approval required for any spend change, new campaign, offer swap, or new brand launch.
LAYER 1 — Orchestrators
Nine specialized orchestrators each owning a distinct domain: media-buyer-agent, email-agent, growth-agent, brand-agent, research-agent, analytics-agent, social-agent, seo-agent, video-agent. Each has its own repo. Each calls Layer 2 for production work.
LAYER 2 — creative-agent
Creative production only. Generates copy and images, posts to Facebook pages. Receives briefs from Layer 1. Never initiates.
LAYER 3 — ai-agency
Monitoring and alerts only. Read-only access. Watches P&L, tracking health, offer caps, email lists. Posts to Slack. No write access to ad accounts.
LAYER 4 — Infrastructure
Warehouse (Supabase operational data) and Knowledge Base (Supabase research data). Internal only — not products, not sold externally.
PRODUCTS
Keygent, Reach, Signal, Bridge — four SaaS products sold externally, built from SSAFF infrastructure.

Structured Experimentation — How media-buyer-agent Learns
Most agents react. media-buyer-agent experiments. The difference is how decisions are logged and measured — and it determines whether the system gets smarter over time or just repeats the same heuristics forever.

Reactive vs Experimental
Reactive (basic)
Experimental (SSAFF)
ROAS drops → pause adset → log action
ROAS drops → form hypothesis → run controlled test → measure → learn
No control group — can't know if it worked
Hold a comparable adset constant to isolate the variable
Outcome: agent_decisions row with outcome pending
Outcome: campaign_experiments row with before/after metrics and result
Learning: Claude reads past decisions by type
Learning: Claude reads structured experiment results with statistical context

The Experiment Framework
Every significant action media-buyer-agent takes follows this structure before executing:

	•	Hypothesis — what do we think is causing the problem and what change should fix it
	•	Variable A — what we are changing (pause adset, reduce budget, swap creative)
	•	Variable B — what we are holding constant as control (comparable adset, same offer, different brand)
	•	Success metric — what we measure to determine if it worked (ROAS delta, CPL change, conversion rate)
	•	Measurement window — when we check the outcome (default 48hrs for ROAS, 7 days for creative)
	•	Result — win / loss / inconclusive — written back to campaign_experiments after measurement window

The Evolution Path
Phase
Capability
Phase 1 — Now (build)
Reactive decisions with structured logging. Every action logged to agent_decisions with outcome measurement at 48hrs.
Phase 2 — 30 days
Structured experiments using campaign_experiments table. Hypothesis + control group + measured outcome for every significant campaign change.
Phase 3 — 90 days
Pattern library. learning-agent reads campaign_experiments, identifies what variables correlate with wins vs losses per brand. Updates media-buyer-agent system prompts with specific learned strategies.
Phase 4 — 6 months
Simulation. With 6+ months of structured experiment data, Claude can reason over historical outcomes to predict impact of a proposed change before executing it. Ask: what happened the last 5 times BDN ROAS dropped below 0.5x and we reduced budget?
Phase 5 — 12 months
The system optimizes beyond human heuristics. Enough data to find non-obvious patterns — audience overlaps, day-of-week effects, offer fatigue cycles — that no human media buyer would identify manually.

campaign_experiments Table — How to Use It Correctly
This table already exists in the schema. The key is that media-buyer-agent must write structured experiments not just log actions.

	•	experiment_type — what category of change: adset_pause, budget_change, creative_swap, offer_rotation, audience_refresh
	•	hypothesis — plain text: 'This adset underperforms because of audience overlap with the GTH campaign'
	•	variable_changed — exactly what was changed with before/after values as jsonb
	•	control_group — what was held constant to isolate the variable
	•	before_metrics — ROAS, CPL, conversion rate at time of decision
	•	after_metrics — same metrics measured at end of measurement window
	•	result — win (metric improved by >10%), loss (metric worsened), inconclusive (change <10%)
	•	confidence — how many similar experiments support this result (builds over time)

What This Unlocks for learning-agent
Once campaign_experiments has 60+ rows with results, learning-agent can answer:

	•	'Pausing adsets during the first 3 days of a campaign consistently worsens ROAS for BDN but improves it for GTH — why?'
	•	'Budget increases above 2x daily average always trigger Facebook's learning phase reset — never do this mid-week'
	•	'Creative fatigue on BDN shows up in CTR drop before ROAS drop — flag at CTR decline not ROAS decline'

These are not rules you program in. These are patterns the system discovers from its own experiment history. That is what separates a reactive agent from a learning system.
